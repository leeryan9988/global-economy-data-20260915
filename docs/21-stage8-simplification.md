# 阶段 8：数据更新链路简化

- 日期：2026-09-16（北京时间）
- 决策：公开网站改为版本化快照自动更新，Supabase 降为可选扩展层。

## 原问题

GitHub Actions 通过 PostgreSQL 连接 Supabase 时反复遇到证书链、凭证和环境差异问题。公开页面实际一直读取仓库快照，因此数据库同步与网站发布形成了没有必要的串联阻塞。

## 新方案

```text
World Bank API → 刷新两份 JSON 快照 → 测试和构建 → 提交 main → Vercel 自动发布
```

## 收益

- 不需要在 GitHub 或 Vercel 保存数据库密码。
- 不依赖 Supabase TLS 证书链。
- 上游失败时不提交，现有公网数据保持可用。
- 每次数据变化都有 Git 历史，可以审查和回滚。
- 与当前页面实际读取方式一致，改动范围小。

## 保留内容

- Supabase/PostgreSQL schema 与迁移。
- 数据库同步实现，供后续需要审计或复杂查询时使用。
- 一次性生产引导 SQL 和历史阶段记录。

## 删除或停用内容

- 删除依赖 `DATABASE_URL` 的生产定时同步工作流。
- 生产就绪检查不再要求数据库连接。
- 健康接口不再把数据库未连接显示为异常状态。
